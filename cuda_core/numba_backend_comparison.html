02 · Trend — FPS vs problem size

The launch-bound → compute-bound crossover

classic (NVVM) mlir (MLIR)

Below ~1024² the sim is host-launch-bound (37 tiny launches/frame) and mlir's lighter dispatch wins ~38%. At/above the crossover the GPU dominates and the two are identical.

03 · Why — host launch overhead

Equal GPU time; unequal dispatch cost

  • Pure GPU time/frame is equal — nsys 0.34 ms both at 512²; ncu: 30/30 regs, ~77% occupancy, 79% SM both.
  • The gap is entirely the Python→driver launch path: 8.6 µs vs 5.3 µs per launch.
  • × 37 launches/frame ≈ the measured wall-vs-GPU gap. mlir dispatches ~38% cheaper.
04 · The vector that flips the headline

CUDA graphs erase the gap

eager graphed

Capture the 37 launches once, replay as one graph launch. Both backends converge to the same FPS (classic gains 3.7× vs mlir 2.5× — it had more overhead to remove). mlir's edge is an eager-path effect only.

10 · Takeaways

Pick on launch model, not codegen

  • The two compilers generate equivalent GPU code — bit-exact, equal GPU runtime, identical occupancy; the SASS edge is an LTO effect classic matches at equal LTO.
  • The only real-world difference is eager-mode launch overhead — mlir ~38% cheaper, matters only below ~1024², and vanishes under CUDA graphs. mlir also compiles ~14% faster.
  • Backend-independent win #1: kernels run in float64 (Python literals) — float32 literals would cut arithmetic on both.
  • Backend-independent win #2: launch-bound below ~1024² — CUDA graphs roughly triple FPS on both.
